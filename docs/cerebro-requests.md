# Cerebro consumer requests — 2026-11-07

Cerebro requested the following, in priority order. The maintainer approved Validator V1 and Runtime per-call headers first, followed by Harness 0.9.12 workflow enforcement and the Lab 0.9.9 blueprint. Cerebro application changes remain outside this scope.

1. **Workflow rules with earlier step outputs. V1 retained:** copyable Harness blueprint, trusted versioned validator, explicit first-review/revision dependencies, bounded feedback/retries, replay/freshness/version protection. Application policy owns insight IDs and the flagged-or-changed predicate. **V2 in Harness 0.9.12:** workflow enforcement tags bind host Guards through existing Runtime 0.9.16 public turns, with finite budgets, fresh accepted dependency facts and durable no-call recovery. See the [contract](https://github.com/B3Cognition/prosaic-harness/blob/v0.9.12/docs/workflow-rules.md) and [Lab blueprint](https://github.com/B3Cognition/prosaic-integration-lab/blob/v0.9.9/docs/workflow-enforcement.md). No copied execution engine or new Runtime release is required.
2. **Per-call OpenAI-compatible headers. In this release:** immutable host-supplied invocation headers, e.g. `x-tokenproxy-no-cache: 1`, forwarded on each provider request without modifying prompt/artifact identity. No model-controlled headers, raw-header persistence or global mutable options.
3. **Accounting request metadata. Runtime 0.9.17:** trusted immutable `ExecutionContext.request_metadata` labels reach `prepare(intent)` before dispatch through the versioned optional context extension. Existing request facts remain available; no raw body/header/prompt projection. None/empty preserves old accounting hashes. Published recorder 0.3.0 needs no DDL; Harness 0.9.12 retains saved labels on resume. New labeled records need the new Runtime reader. See [bounds, identity and migration](accounting.md#request-metadata-v1). Lab 0.9.10 will qualify the released train and copyable blueprint separately; a Runtime release alone does not certify a partial Lab train.
4. **Effort in results. Deferred:** per-provider-call resolved effort, exact effort fields and format actually sent, including retries and defaults/omission. Distinguish requested/sent/provider-confirmed; sent does not prove honored. Reuse evidence in accounting without inventing model acknowledgments.
5. **Separate rule-repair allowance. Deferred:** explicit bounded initial and repair allowances, distinguish repair from transport retries. A hard total of1 cannot silently authorize2 calls. Keep token/tool/deadline/cost caps and unknown-effect recovery authoritative; show consumed allowances in evidence.
6. **Written identity guarantee. Deferred:** enumerate artifact digest, rules fingerprint, prepared input, workflow/binding and validator identity fields, absent/default omission and intentional changes. Golden old/new fixtures and a versioned migration/readmission policy; every release declares identity impact. Do not promise all hashes are unchanged when semantic bindings change.
7. **Version-specific release notes. Backfill completed; publisher enforcement deferred:** current releases have meaningful notes, and the documentation refresh backfills generic historical notes, including Runtime 0.9.14 and 0.9.15. See [release history](releases.md). Every future release must state behavior, compatibility, identity, migration and verification limits. Automating rejection of missing/generic notes remains future work; existing package bytes and receipts remain immutable.

Acceptance when revisiting: exercise both supported synthetic provider wires where applicable; source and isolated installed-wheel consumers; persisted resume/identity and accounting failure paths; no live inference without explicit authorization.
